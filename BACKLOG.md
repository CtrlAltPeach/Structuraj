# Бэклог

## Читаемый вид значений

**Заведено:** 2026-08-25 · **Статус:** не начато

Сейчас значение показывается ровно так, как лежит в файле. Для машинных данных
это нечитаемо: экранированный JSON, эпоха вместо даты, `\n` вместо переноса.
Нужен слой, который приводит сырой текст к человекочитаемому виду — с
возможностью в один клик вернуться к сырому.

### Случаи, которые видно уже сейчас

| что в файле | что хочется увидеть |
|---|---|
| `"{\"id\":1,\"ok\":true}"` | развёрнутый и подсвеченный JSON |
| `"строка\nвторая\tтретья"` | реальные переносы и табы |
| `1735689600`, `1735689600000` | `2025-01-01 00:00` |
| `"2025-01-01T00:00:00.000Z"` | `2025-01-01 00:00` в местной зоне |
| `"eyJhbGciOi…"` | распознать base64/JWT, показать содержимое |
| `"%D0%9F%D1%80%D0%B8"` | `Приве` — снятое URL-кодирование |
| `"При"` | `При` — снятые unicode-эскейпы |
| строка на 40 КБ | свёрнутый превью с раскрытием |

### Как это должно работать

1. Распознавание по содержимому значения, не по имени ключа: имена в реальных данных врут.
2. Переключатель **сырое / читаемое** в панели значений. Умолчание — читаемое, но выбор запоминается.
3. Режим применяется и к таблице «Все вхождения», и к вкладке «Запись целиком».
4. Копирование всегда отдаёт **сырое** значение, что бы ни было на экране.
5. Распознавание — во фронтенде, поверх уже полученной страницы. Индекс не трогаем: он должен хранить оригинал, иначе сортировка и фильтр начнут врать.

### Открытые вопросы

1. Эпоха в секундах или миллисекундах — определять по величине числа или спрашивать? Порог `10^11` разделяет их, но не надёжно.
2. Часовой пояс для дат: местный, UTC или переключатель?
3. Что делать со значением, которое распозналось неправильно — нужен ли способ выключить конкретное правило для конкретного ключа?
4. Длинные строки: раскрывать в строке таблицы или в отдельной панели сбоку?
5. Нужно ли распознавание в фильтре по значению — искать `2025-01-01` по полю, где лежит эпоха?

### Ограничение, о которое споткнётся реализация

В таблице значение приходит обрезанным на 4096 символах (`db.rs: MAX_TEXT`).
Экранированный JSON длиннее этого развернуть не получится — придётся дочитывать
запись через `getRecord`. Либо поднимать порог, либо ходить за полным значением
по требованию.

## Перевод значений ключей

**Заведено:** 2026-08-25 · **Статус:** не начато

Добавить перевод текстовых значений выбранного ключа на другие языки прямо в
таблице «Все вхождения» и во вкладке «Запись целиком».

### Требования

1. Исходное значение всегда остаётся доступным и используется для копирования, фильтрации и сортировки.
2. Пользователь выбирает язык назначения и может быстро включать или выключать перевод.
3. Перевод выполняется только по явному действию пользователя, пакетно для видимой страницы.
4. Результаты кэшируются локально по сочетанию «исходный текст + язык», чтобы не переводить повторно.
5. До реализации выбрать провайдера, описать передачу данных наружу и предусмотреть полностью локальный режим.

## Сборка и релиз через GitHub Actions

**Заведено:** 2026-08-25 · **Статус:** не начато

Сейчас релиз собирается вручную на рабочей машине: поднять версию, `npm run tauri build`,
`gh release create` со списком файлов. Три шага, каждый можно забыть или сделать
не в том порядке. Нужен workflow, который делает это по пушу тега.

### Что должно происходить

1. Триггер — пуш тега вида `v*`.
2. Проверка, что версия в `src-tauri/tauri.conf.json` и в `package.json` совпадает с тегом. Не совпала — сборка падает сразу, а не выкладывает файлы с чужим номером.
3. `cargo test` и `tsc --noEmit` до сборки: релиз с непроходящими тестами выкладываться не должен.
4. `tauri-apps/tauri-action` собирает установщики и создаёт черновик релиза с приложенными файлами.
5. Публикация — руками, после проверки. Автопубликация оставляет слишком мало времени передумать.

### Что учесть

* Кэш Rust (`Swatinem/rust-cache`) — без него каждая сборка тянет весь Tauri с нуля, это минуты.
* `Cargo.lock` в репозитории есть, сборка воспроизводима.
* `src-tauri/.cargo/config.toml` намеренно не в репозитории, поэтому в CI используется каталог `target/` по умолчанию — так и надо.
* Заметки к релизу: писать руками или собирать из коммитов? Пока они писались руками и получились полезнее, чем список коммитов.

### Открытые вопросы

1. Подписывать ли установщики? Без сертификата SmartScreen ругается у каждого, кто скачает. Сертификат стоит денег и требует хранения ключа в секретах репозитория.
2. Собирать ли под ARM64 — это отдельная матрица и вдвое дольше.
3. Гонять ли тесты на каждый push в `main`, а не только на тег?

## Сборки под Linux и остальные форматы macOS

**Заведено:** 2026-08-25 · **Статус:** не начато

Портативная сборка под macOS делается отдельно и в этот пункт не входит.
Здесь — всё остальное: Linux целиком и установочные форматы macOS.

### Код к переносу готов

Аудит ядра на платформенные зависимости: единственный `cfg` — стандартный
`windows_subsystem` в `main.rs`, на других системах игнорируется. Жёстко зашитых
путей нет, всё через `PathBuf`. `app_local_data_dir()` и `temp_dir()`
кроссплатформенные. Строка `"C:/тест"` в тестах — подпись для markdown, не путь.

Непроверенным остаётся только слой вебвью: на Linux это WebKitGTK, на macOS —
WKWebView, и наш CSS они могут отрисовать иначе, чем Chromium на Windows.

### Linux

* **AppImage** — портативный формат: один файл, `chmod +x`, запуск. Плюс `.deb` и `.rpm` для установки.
* Собирать только на **Ubuntu 22.04**: Tauri v2 требует `webkit2gtk-4.1`. Собранное на 24.04 на 22.04 не запустится, обратное работает.
* Раннер `ubuntu-22.04` в GitHub Actions, зависимости ставятся через `apt`.

### macOS: установочные форматы

* `.dmg` — формат по умолчанию у Tauri, привычный способ раздачи.
* Архитектур две: Apple Silicon и Intel. Либо две сборки, либо универсальный бинарник через `--target universal-apple-darwin`.
* **Gatekeeper строже SmartScreen.** Скачанное неподписанное приложение macOS не откроет вовсе. С macOS 15 Sequoia обход правым кликом убрали — надо идти в Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть», либо снимать карантин через `xattr -dr com.apple.quarantine`.
* Убирается только сертификатом Developer ID и нотаризацией: аккаунт Apple, 99 долларов в год.

### Что CI проверит, а что нет

Кросс-компиляция с Windows невозможна, нужны раннеры macOS и Linux — для открытых
репозиториев они бесплатны.

| проверяемо | непроверяемо |
|---|---|
| те же 8 тестов на каждой системе: обход папки, разбор JSON, канонические пути, оба режима дерева, пагинация, чтение записи | отрисовка интерфейса в чужом вебвью |
| сборка и упаковка | системный диалог выбора папки |
| | поведение клавиатуры в дереве |

Пока никто с реальной машиной не отпишется, артефакты под macOS и Linux
в релизе стоит помечать экспериментальными.

### Открытые вопросы

1. Ставить ли `.deb` и `.rpm` рядом с AppImage или ограничиться портативным форматом?
2. Универсальный бинарник под macOS или две отдельные сборки? Универсальный вдвое тяжелее.
3. Стоит ли вообще класть непроверенные артефакты в общий релиз, или держать их отдельным пререлизом?
