# Руководство

## Что делает приложение

Показывает, **что вообще лежит** в куче JSON-файлов, и даёт по любому ключу
посмотреть все его значения сразу — из всех файлов, с сортировкой и фильтром.

Исходные файлы не меняются никогда. Единственное, что приложение пишет в твою
папку — `STRUCTURE.md`, и только по нажатию кнопки.

## 1. Выбрать папку

Кнопка **«Выбрать папку»** в шапке. Дальше папка обходится рекурсивно.

Берутся файлы `.json`, `.jsonl`, `.ndjson`. Каталоги `.git` пропускаются.
Пока идёт скан, видна полоса прогресса: сколько файлов пройдено, сколько записей
разобрано и какой файл читается сейчас.

Битые файлы скан не останавливают — они уходят во вкладку «Ошибки».

После скана в шапке появляются счётчики: файлов, записей, ключей, значений, объём.

## 2. Дерево структуры

Слева — единая структура по **всем** файлам сразу. У каждого ключа справа стоит
счётчик: сколько раз он встретился.

### Два режима

Переключатель в шапке, пересканирование не нужно.

* **по имени** (по умолчанию) — все одноимённые ключи слиты в один узел. Бейдж `×N путей` показывает, что ключ живёт в нескольких местах; наведи мышь, чтобы увидеть список. В таблице значений появляется колонка «Путь».
* **по пути** — `user.name` и `order.name` остаются разными узлами.

Режим «по имени» удобнее, когда надо ответить «какие вообще бывают ключи».
Режим «по пути» — когда важно, где именно ключ лежит.

### Клавиатура

Стрелки двигают выделение, а не прокручивают панель.

| клавиша | действие |
|---|---|
| ↑ / ↓ | предыдущий / следующий ключ |
| → | развернуть узел; если уже развёрнут — шаг вниз |
| ← | свернуть узел; если это лист — прыжок к родителю |
| Home / End | первый / последний ключ |
| Enter, пробел | свернуть или развернуть |

Выбранная строка сама подкручивается в зону видимости.

### Поиск и фильтр

**Поиск ключа** — подстрока по имени или по пути. Совпадения раскрываются
автоматически, родительские ветки остаются видны.

**Скрыть пустые** — убирает ключи, у которых во всех записях значение `null`,
пустая строка, `[]` или `{}`. Ветка отсекается целиком: объект, внутри которого
одни `null`, исчезает вместе с содержимым. `false` и `0` пустыми не считаются —
это значения.

Такие ключи и без фильтра помечены серым бейджем `пусто`.

### Массивы

Массив — контейнер: собственных значений он не показывает, он нужен только в
структуре. Ключи объектов внутри массива висят прямо под ним. Если массив
скалярный, его значения лежат в дочернем узле `[]`.

Заглушка «массивы значений не показывают» появляется, только если ключ —
массив во **всех** вхождениях. Ключ со смешанными типами (в одних файлах строка,
в других массив) свои строковые значения показывает: в подписи узла видно
перечисление вроде `string | array`, а не слово «массив».

## 3. Все вхождения

Основная вкладка. Одна строка — одно вхождение выбранного ключа.

| колонка | что в ней |
|---|---|
| Файл | путь относительно выбранной папки |
| № записи | номер записи внутри файла, с нуля |
| Путь | канонический путь этого конкретного значения |
| Тип | `string`, `number`, `null`, `bool`, `object`, `array` |
| Значение | текстовое представление |

**Сортировка** — клик по заголовку, повторный клик переворачивает порядок.
Сортировка по значению ставит сначала числа по возрастанию, потом строки по
алфавиту.

**Фильтр** — подстрока в значении, срабатывает через 250 мс после последнего
нажатия. **Выпадающий список файлов** ограничивает выборку одним файлом.

**Страницы** по 200 строк, кнопки «назад» и «вперёд». Слева от них видно
`1–200 из 12 480`.

Кнопка **«запись»** в конце строки открывает эту запись целиком на соседней
вкладке — листалка встаёт ровно на неё.

Значение длиннее 4096 символов обрезается и помечается синим `…`. Полную строку
видно на вкладке «Запись целиком» — там текст читается из исходного файла.

## 4. Запись целиком

Листание однотипных объектов.

* Кнопки **«пред.»** и **«след.»**, стрелки ← и → (когда фокус не в дереве и не в поле ввода)
* Поле с номером — прыжок к нужной записи
* Справа видно, из какого файла и какая это запись

Выборка ограничена записями, в которых есть выбранный ключ. Строки с этим ключом
подсвечены.

## 5. Ошибки

Файлы, которые не разобрались: имя, номер строки (для `.jsonl`) и сообщение
парсера. С одного файла попадает не больше 100 ошибок.

Счётчик рядом с названием вкладки показывает, есть ли вообще ошибки.

## 6. Экспорт структуры

Кнопка **«Экспорт STRUCTURE.md»** пишет дерево в корень выбранной папки в том
режиме, который сейчас включён.

```markdown
- **$** — `массив` · 5
  - **id** — `number` · 7 · путей: 2
  - **name** — `string` · 11 · путей: 4
  - **note** — `null` · 3 · пусто
  - **tags** — `массив` · 3
    - **tags[]** — `string` · 3
```

Расшифровка строки: имя ключа, тип или `массив`, счётчик вхождений, затем при
необходимости `путей: N` (сколько путей слито в этот узел) и `пусто`.

## Что стоит знать

1. Смена папки полностью пересобирает индекс — старый набор теряется.
2. Индекс лежит в `%LOCALAPPDATA%\com.structuraj.app\index.sqlite` и пересоздаётся при каждом скане. В папку с данными приложение ничего не кладёт.
3. Корневой узел `$` может показываться одновременно как массив и как объект, если в одних файлах верхний уровень массив, а в других объект.
4. В режиме «по имени» ключ подвешивается к самому частому родителю. Если `name` чаще встречается в корне, чем в `user`, то под `user` его не будет — он уехал наверх. Переключись на «по пути», если нужна точная вложенность.
5. Приложение работает только на чтение. Редактирования значений нет.
